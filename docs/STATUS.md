## สิ่งที่ยังไม่ได้ทำหรือยังไม่ได้ทดสอบ (ตามจริง)

1. **เว็บจริงยังเป็นเวอร์ชัน 15 ต.ค.** ต้อง push และ deploy เวอร์ชันนี้ตาม `docs/DEPLOY.md` หัวข้อ 6.1 และเมื่อ 17 ต.ค. `/api/health` ของเว็บจริงตอบไม่สำเร็จ ควรตรวจ Logs ใน Railway (ส่วน Infrastructure as Code `.railway/railway.ts` ยังไม่ได้ทดลอง apply จริง)
2. **Google sign-in ยังไม่ได้ทดสอบกับ Google จริง** เพราะต้องใช้ OAuth client ของสถานศึกษา โค้ด กติกา allowlist และการเพิ่มเข้าห้องอัตโนมัติผ่าน smoke test แล้ว
3. **ที่เก็บไฟล์ใบงานเป็นดิสก์ของเซิร์ฟเวอร์** (บน Railway ใช้ volume) มี interface สำหรับเพิ่ม S3-compatible storage ภายหลังแต่ยังไม่ได้เขียน
4. **การตรวจเนื้อหาทำโดยทีมตรวจที่เป็น AI** แม้จะคำนวณซ้ำทุกข้อและเทียบมาตรฐาน ครูผู้สอนควรตรวจประเด็นในหัวข้อ 8 ของรายงานหลักสูตรก่อนใช้จริง โดยเฉพาะ
   - ข้อกำหนดตามมาตรฐานการติดตั้งทางไฟฟ้า วสท. ฉบับที่สถานศึกษาใช้ (เช่น ขนาดสายวงจรย่อยขั้นต่ำ 2.5 mm², จุดที่ต้องติด RCD)
   - แถบความคลาดเคลื่อนสีเทา: หลักสูตรใช้ ±0.05 % ตามแบบ EIA ที่ผู้ผลิตจำนวนมากยังใช้ และอธิบายว่า IEC 60062:2016 ใช้เทา ±0.01 % / ส้ม ±0.05 % (ตั้งใจคงไว้)
   - คลังข้อสอบสัปดาห์ 16 มีสัดส่วนระดับ Bloom ต่างจากเป้าเล็กน้อย (5/8/10/7/2 เทียบ 5/7/10/6/2) ตั้งใจคงไว้
5. **ภาพจากเอกสารต้นฉบับไม่ได้นำมาใช้** เพราะการตรวจพบว่าเกือบทั้งหมดเป็นภาพของบุคคลที่สาม (เว็บร้านค้า บล็อก Shutterstock ฯลฯ) หลายภาพมีลายน้ำหรือไม่ระบุที่มา จึงวาดใหม่เป็น SVG ทั้งหมด
6. **ห้องทดลองเสมือนเป็นแบบจำลองเพื่อการเรียนรู้หลักการ** ไม่จำลองความไม่เป็นอุดมคติบางอย่าง (เช่น ความต้านทานขาออก 50 Ω ของเครื่องกำเนิดสัญญาณ การอิ่มตัวของแกนเหล็ก) ซึ่งระบุไว้ในกล่องข้อสมมติของแต่ละห้อง
7. **E2E ตรวจคำตอบตัวเลขของภารกิจห้องทดลองตามเฉลยในเนื้อหา** ไม่ได้อ่านค่าจากหน้าจอแบบจำลอง ความสอดคล้องระหว่างเฉลยกับแบบจำลองตรวจโดยผู้ตรวจวิชาการด้วยการคำนวณจาก model.ts แทน
8. **ภาพถ่ายของจริง (21 ต.ค.)** ใส่ภาพอุปกรณ์จาก Wikimedia Commons แล้ว 40 จาก 43 ภาพ อีก 3 ภาพหาภาพที่ถูกต้องไม่ได้ จึงยังใช้ภาพวาด รายละเอียดอยู่ใน `docs/curriculum/PHOTO_PLAN.md`
9. การคลิกก่อนหน้าเว็บโหลด JavaScript เสร็จจะยังไม่ทำงาน (พฤติกรรมปกติของเว็บแอป ชุดทดสอบรอให้หน้าโหลดเสร็จก่อน)
